## 지금까지의 핵심 성과

1. **법제처 국가법령정보 공동활용 Open API 검증 완료**
   - "대한민국 법률 전부 정리 API"로 가능 ✅ / **연도별(연혁)은 별도 target(`eflaw`)** ✅
   - 감염병예방법 = 법령ID `001792`, **67개 시행 버전(1954→2026)** 전량 수집
2. **감염병예방법 연혁 1차 정리 완료** — 제정→전부개정→급체계 개편까지 마일스톤·용어·분류·개수
3. **법정감염병 91종 전 종 수록**(⑤) — 현행 고시 제2026-9호 조문 전문을 API로 직접 대조해 총수 검산
   - 제1급 18 · 제2급 21 · 제3급 28 · 제4급 24 = 전수 67 + 표본 24
   - **니파바이러스감염증 제1급 지정(2025.9.8)** 을 급수변동 원장에 반영
4. **2024 질병관리청 백서 본문 전량 요약**(③) — 목차가 아니라 본문 근거. 백일해 164.5배 등 실측치
5. **백서 원문 접근성 실측 점검**(③) — **2004~2011·2014-2015 등 9판이 누리집에서 사라진 사실**을 확인
6. **'효과 데이터' 층 개통**(⑦ P0) — 변경 이력(§01)과 발생 통계를 처음으로 연결
   - 매독 "2024년 2,790명 폭증"을 **동일 신고범위로 재계산해 반증**: 2018년 2,280 → 2024년 **1,519(△33.4%)**
   - 「감염병 신고 현황 연보」 2016~2025 전수감시 시계열 **73종×10년 기계가독화**
   - 신고범위·진단기준 **단절점 4건 신규 발견**(B형간염 2016·VRSA 2019·매독 2024·쯔쯔가무시증 2025) → 원장 10건 → **16건**
7. **단절점 검사기 배포**(⑧) — 아카이브를 **쓸 수 있는 도구**로 전환한 첫 산출물
   - 68종 × 두 연도 조합에 대해 🟢비교 가능 / 🟡해석 주의 / 🔴비교 불가를 판정
   - 결측을 **미지정 / 표본감시 / 항목이동** 세 가지로 구분 — 이걸 뭉개면 매독 사례를 정확히 틀리게 답한다
   - 보고서·기사에 붙여 쓸 **인용 각주 자동 생성**
8. **재현 가능한 수집 파이프라인** — 누구나 스크립트로 최신 데이터 갱신 가능

## 빌드와 점검

```bash
python3 scripts/build_portal.py     # 조립: 연대기·검사기 감싸기 + 머리글·메뉴·인쇄 도구 주입 + 자료 점검
python3 scripts/check_datasets.py   # 자료 점검만 따로. 고칠 것이 있으면 1을 낸다
```

`build_portal.py`는 끝에 점검을 같이 돌리되 거기서 멈추지 않는다. 쪽은 이미 다 써
놓았고, 자료 문제는 사람이 보고 정할 것이라서다. 딱 잘라 판정이 필요하면
`check_datasets.py`를 따로 돌린다.

점검이 보는 것

| 보는 것 | 어긋나면 |
|---|---|
| 원장 파일이 비어 있지 않고 읽히는가 | 오류 |
| 연도 열의 범위가 말이 되는가, 통째로 빈 해가 있는가 | 오류 / 경고 |
| 갈래끼리 부르는 감염병 이름이 서로 닿는가 | 오류(연대기 기준) / 경고(도감·연보) |
| 각 쪽의 인코딩·언어·제목·설명, 루트절대 경로, 중복 id | 오류 / 경고 |
| 데이터 센터가 내건 파일이 실제로 있는가 | 오류 |

갈래마다 괄호 약칭을 붙이기도 떼기도 한다(연대기는 `중동호흡기증후군(MERS)`,
시뮬레이터는 `중동호흡기증후군`). 붙인 것·뗀 것·약칭을 지운 것을 모두 열쇠로 삼아
맞춰 보므로, 표기가 조금 달라도 연결이 끊긴 것으로 잘못 잡지 않는다.

각 쪽을 따로 다시 만들 때는 그 쪽의 빌더를 돌린 뒤 `build_portal.py`를 한 번 더
돌려야 머리글·메뉴가 붙는다. 예: `python3 scripts/build_sim.py && python3 scripts/build_portal.py`

## 쉬운 말

중학교를 마친 사람이 읽을 수 있어야 한다는 기준으로 손본 것들이다.
본문 글자는 바꾸지 않는다 — 화면에서 감싸거나 위에 얹기만 하므로 자료·통계·출처에는 영향이 없다.

| 파일 | 하는 일 |
|---|---|
| `scripts/plain_glossary.py` | 어려운 낱말의 풀이. 각 쪽에서 그 말이 처음 나온 자리에만 뜻이 붙는다 |

## 상황판 이메일 — 아직 꺼져 있다

RSS(`portal/daily/feed.xml`)는 지금도 돌아간다. 이메일은 저장소에 값을 넣어야 켜진다.
이 값들은 운영자만 넣을 수 있다.

| 종류 | 이름 | 쓰임 |
|---|---|---|
| Secret | `SMTP_SERVER` | 보내는 서버 주소 |
| Secret | `SMTP_USER` | 계정. 보내는 사람 주소로도 쓴다 |
| Secret | `SMTP_PASS` | 계정 비밀번호(앱 비밀번호 권장) |
| Secret | `NEWSLETTER_TO` | 받는 주소. 쉼표로 여럿 |
| Variable | `SUBSCRIBE_FORM_URL` | 신청 폼 주소. 넣으면 상황판의 신청 칸이 열린다 |

`SMTP_USER`가 비어 있으면 발송 단계를 건너뛴다. 새 항목이 없는 날은 값이 있어도 보내지 않는다.
`SUBSCRIBE_FORM_URL`이 비어 있는 동안 상황판은 신청 칸을 잠그고 그 사실을 화면에 적는다 —
없는 창구를 열어 둔 것처럼 보이지 않게 한다.
